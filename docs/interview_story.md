# Interview Story｜AI Test Factory

## Why I Built AI Test Factory

I wanted to explore how AI can assist automotive testing workflows in a more structured and reusable way.

Instead of using AI only for simple conversations, I focused on building a lightweight engineering-oriented workflow system.

The goal was to simulate how testing engineers organize testing logic, generate testing artifacts, and improve workflow efficiency.

---

## What Problem It Solves

Traditional testing workflows often involve repetitive documentation work.

Engineers need to repeatedly write:

- Test points
- Test cases
- Bug reports

AI Test Factory explores how AI can help engineers reduce repetitive work while preserving engineering thinking.

---

## Why Automotive Testing

Automotive electronics testing contains many structured scenarios such as:

- IVI black screen
- Reverse camera failure
- Dashboard reboot issues

These scenarios are suitable for workflow standardization and AI-assisted generation.

---

## Why Feishu + OpenClaw

I wanted the workflow to be more team-oriented rather than a standalone local script.

Feishu provides:

- Better collaboration
- Easier team adoption
- Lower operational barriers

OpenClaw provides:

- Workflow orchestration
- AI integration capability
- Multi-platform extensibility

The combination allows AI workflows to move closer to real engineering collaboration environments.

---

## Core Design Thinking

The project follows several principles:

- Structure-first workflow
- Minimal main pipeline
- Reusable outputs
- Lightweight collaboration
- Engineering-oriented AI usage

---

## Future Direction

In future versions, I want AI Test Factory to evolve into:

```text
A collaborative AI-assisted testing platform
```

instead of remaining a simple generation tool.
